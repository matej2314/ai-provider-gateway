# Dictionary — AI Provider Gateway

This document establishes a shared vocabulary among project users, integrators, and the implementation. JSON field names are technical; descriptions are in English.

## Facade vs provider runtime

The gateway separates **two independent concepts**. Confusing them is the most common semantic mistake among integrators.

**Editorial rule:** the first occurrence of the word “OpenAI” in a document should have a qualifier — **facade**, **adapter (runtime)**, or **upstream** (api.openai.com).

### Canonical terms

| Term                                | Path                                                                                              | Role                                                                                                        |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **OpenAI facade**                     | `src/integrations/openai/`                                                                           | Translates HTTP in OpenAI Chat Completions shape → `ChatService`; **does not** call api.openai.com              |
| **OpenAI adapter** (provider runtime) | `src/providers/factories/create-openai-provider.ts`, `create-openai-compatible-provider-instance.ts` | Calls the OpenAI SDK for `type: openai` or `openai-compatible` in YAML; **does not** handle `/api/v1/openai/*` routes |
| **Anthropic facade**                  | `src/integrations/anthropic/`                                                                        | Anthropic Messages API shape → `ChatService`                                                              |
| **Anthropic adapter**                 | `src/providers/factories/create-anthropic-provider.ts`                                               | Calls the Anthropic API for `type: anthropic` in YAML                                                              |

### Responsibility matrix (OpenAI)

| Question                 | OpenAI facade                 | OpenAI adapter                                                        |
| ----------------------- | ----------------------------- | --------------------------------------------------------------------- |
| Where in the code?         | `src/integrations/openai/`    | `src/providers/factories/create-openai-provider.ts`                   |
| Who uses it?   | Cursor, OpenAI-shaped clients | `ChatProviderCallService` via YAML                                  |
| Client auth            | Bearer = gateway key        | —                                                                     |
| Vendor auth         | —                             | `OPENAI_API_KEY` / `apiKeyRef`                                        |
| Requires the other layer? | No                           | No                                                                   |

### Responsibility matrix (Anthropic)

| Question                 | Anthropic facade                         | Anthropic adapter                                       |
| ----------------------- | ---------------------------------------- | ------------------------------------------------------- |
| Where in the code?         | `src/integrations/anthropic/`            | `src/providers/factories/create-anthropic-provider.ts`  |
| Who uses it?   | Claude Code, Messages API clients        | `ChatProviderCallService` via YAML                    |
| Client auth            | `x-api-key` = gateway key              | —                                                       |
| Vendor auth         | —                                        | `ANTHROPIC_*` / `apiKeyRef`                             |
| Requires the other layer? | No                                      | No                                                     |

| Concept               | Layer                        | Role                                                                                                                       | What it **does not** mean                                                                                    |
| --------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **Integration facade** | `src/integrations/` — HTTP     | Implements the **shape** of the OpenAI or Anthropic Messages contract | Connection to api.openai.com / Anthropic API; presence of an `anthropic` or `openai` provider in config |
| **Provider runtime**  | `src/providers/` — SDK adapter | Calling an LLM at a specific vendor (key from `.env`, `modelId` from YAML)                                                     | Choice of HTTP surface by the client                                                                    |

**LLM routing** is purely **configuration-driven**:

1. The client supplies `model` (facades) or `modelAlias` (native API) — this is an **alias** from `gateway.config.yaml`, not a vendor `modelId`.
2. Entry `models[<alias>]` points to `providerInstance` and `modelId`.
3. `ProviderRegistryService` returns the `AIProvider` adapter for that instance.

Example: a request to `/api/v1/openai/chat/completions` with `model: "gemini-flash"` may hit Google Gemini if the alias is configured that way. Likewise `/api/v1/anthropic/messages` **does not require** an `anthropic` provider in YAML.

**Authorization on facades:** vendor-style headers (`Authorization: Bearer`, `x-api-key`) carry the **gateway client key** from the allowlist (`GATEWAY_KEY_*`), **not** an OpenAI.com or Anthropic API key. Provider keys live only in `.env` (`apiKeyRef`).

**Related documents:** `integrations.md`, `openai-contract-integration.md`, `anthropic-messages-integration.md`, `provider-openai-runtime.md`, [`SECURITY.md`](../SECURITY.md).

## `systemFingerprint` — semantics and providers

| Layer                                              | Behavior                                                                                                                                          |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Gateway contract** (`ChatResponseDto`, SSE `done`) | Optional `systemFingerprint` field — **pass-through** from the adapter; omitted in JSON/SSE when absent                                           |
| **OpenAI (upstream)**                                | `system_fingerprint` in Chat Completions — identifier of the OpenAI backend configuration snapshot                                                      |
| **Anthropic**                                        | No field in Messages API — value **always** omitted                                                                                             |
| **Google Gemini**                                    | No `system_fingerprint`; there are `responseId` (response ID) and `modelVersion` — **different semantics**, gateway **does not** map them to `systemFingerprint` |
| **OpenAI adapter** (`create-openai-provider.ts`)     | Extracts `system_fingerprint` in Chat Completions (`chat-completions.adapter.ts`); Responses API — no equivalent                               |
| **OpenAI facade**                                    | Maps `systemFingerprint` → `system_fingerprint` when the field is set                                                                          |
| **Anthropic facade**                                 | No equivalent in the Anthropic Messages API contract                                                                                               |

**Integrator:** do not expect `systemFingerprint` for aliases on Anthropic or Google. With the OpenAI facade and an alias pointing at another backend, the field usually **will not appear**, even though the client “talks” OpenAI API shape.

## Generation parameters (C0–C7 extensions)

### Parameter mapping onto providers

Field in **`params`** (native chat) / OpenAI / Anthropic facade mapping → **`ProviderCallOptions`** → SDK adapter. **Runtime adapter** matrix (`src/providers/factories/`):

| Gateway parameter   | SDK field (indicative)                                                                                                           | Anthropic                                                             | Google Gemini                                          | OpenAI (adapter)                                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `temperature`      | `temperature`                                                                                                                      | ✅ passed                                                       | ✅ passed                                        | ✅ Chat Completions + Responses                                                                                              |
| `maxOutputTokens`  | `max_tokens` / `maxOutputTokens` / `max_output_tokens`                                                                             | ✅                                                                    | ✅                                                     | ✅                                                                                                                           |
| `topP`             | `top_p` / `topP`                                                                                                                   | ✅ \*                                                                 | ✅                                                     | ✅                                                                                                                           |
| `stop`             | `stop_sequences` / `stopSequences` / `stop`                                                                                        | ✅                                                                    | ✅                                                     | ✅ Chat Completions                                                                                                          |
| `frequencyPenalty` | `frequency_penalty`                                                                                                                | ❌ ignored                                                         | ❌ ignored                                          | ✅ Chat Completions                                                                                                          |
| `presencePenalty`  | `presence_penalty`                                                                                                                 | ❌ ignored                                                         | ❌ ignored                                          | ✅ Chat Completions                                                                                                          |
| `seed`             | `seed`                                                                                                                             | ❌ ignored                                                         | ✅ passed                                        | ✅ Chat Completions                                                                                                          |
| `responseFormat`   | `output_config.format` (Anthropic) / `response_format` + `response_schema` (Google) / `response_format` or `text.format` (OpenAI) | ✅ `json_object` + optional `jsonSchema`                            | ✅ same as above                                                | ✅ Chat Completions + Responses (`json_object`)                                                                              |
| `topK`             | `top_k` / `topK`                                                                                                                   | ✅ (priority over `topP` / `temperature`)                             | ✅                                                     | ❌ ignored                                                                                                                |
| `thinkingEnabled`  | `thinking` (Anthropic) / `thinkingConfig` (Google) / `reasoning.effort` (OpenAI Responses)                                         | ✅ `thinking: { type, budget_tokens?, display }`                      | ✅ `thinkingConfig: { includeThoughts }` (Gemini 3.0+) | ✅ Responses API (`reasoning.effort` + `reasoning.summary: auto`); adapter `type: openai` in `create-openai-provider.core.ts` |
| `thinkingBudget`   | token budget / effort level / thinkingLevel                                                                                        | ✅ number → `thinking.budget_tokens`; string → `output_config.effort` | ✅ number → `thinkingBudget`; string → `thinkingLevel` | ✅ string effort → `reasoning.effort`; number — surface validation (Responses)                                                |

\* **Anthropic — one randomness parameter:** the adapter sends **exactly one** of `top_k`, `top_p`, `temperature` — priority in `resolveAnthropicSamplingParams()`: **`topK` > `topP` > `temperature`** (`create-anthropic-provider.ts`). Merge of YAML + body may set multiple values in `ProviderCallOptions`, but only the priority winner reaches the SDK. Details: `configuration.md`.

**Merge with YAML `policy.params.defaults`:** in `resolveProviderCallOptions`, default values from YAML are loaded for `temperature`, `maxOutputTokens`, `topP`, `frequencyPenalty`, `presencePenalty`, `seed`, `thinkingEnabled`. Fields **`topK`**, **`stop`**, **`responseFormat`**, and **`thinkingBudget`** come **only from the body** (when provided and allowed in `allowOverrides`); the Zod schema (`gateway-config.schema.ts`) **does not** define them in `defaults`.

**OpenAI facade vs OpenAI adapter:** module `src/integrations/openai/` translates the client contract (e.g. Cursor) into `ChatRequestDto` — this is an **HTTP facade**, not a call to api.openai.com. Runtime adapter `type: openai` in `src/providers/` (factory `create-openai-provider.ts`) is a **separate** piece: it only concerns routing of a configured alias. The same distinction applies to the **Anthropic facade** (`src/integrations/anthropic/`) vs adapter `type: anthropic` — the Messages API facade does not guarantee an Anthropic backend.

**Anthropic facade vs Anthropic adapter:** field `model` in `/api/v1/anthropic/messages` = `modelAlias`; the backend may be any `providerInstance` from YAML (e.g. Google) if the alias points there.

### Field dictionary

| Term                         | Definition                                                                                                                                                   | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **topP** (nucleus sampling)    | Randomness control parameter — the model considers only the smallest set of tokens whose cumulative probability ≥ topP (0–1).       | **Google / OpenAI (target):** can combine with `temperature` in defaults. **Anthropic:** adapter sends **one** randomness parameter — priority `topK` > `topP` > `temperature`. Higher value (e.g. 0.95) = more diverse responses.                                                                                                                                                                                                                                                                                                                             |
| **stop** (stop sequences)      | List of character sequences that stop text generation by the model.                                                                                      | **Vendor-agnostic**: OpenAI `stop` (string \| string[]), Anthropic `stop_sequences` (array), Google `stopSequences` (array). Useful for controlling response length and structure (e.g. `["\n\n", "###"]`). Gateway accepts `string \| string[]` — converts string → array for Anthropic/Google.                                                                                                                                                                                                                                                                     |
| **frequencyPenalty**           | Penalizes tokens based on their frequency in the text so far (-2 to 2). Positive values reduce the likelihood of verbatim line repeats. | Accepted in the native API and OpenAI facade (`ChatParamsDto`, `openai-request.mapper.ts`). Adapters **`anthropic`** / **`google`** **do not pass** this parameter to the SDK (silent skip).                                                                                                                                                                                                                                                                                                                                                                         |
| **presencePenalty**            | Penalizes tokens based on their presence in the text so far (-2 to 2). Positive values increase the likelihood of talking about new topics.  | Like `frequencyPenalty` — accepted in the API, **ignored** by `anthropic` / `google` adapters.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **seed**                       | Integer for deterministic sampling — same seed + same parameters ≈ nearly identical response.                           | **OpenAI + Google**: supported natively. **Anthropic**: not supported. Useful for A/B tests and reproducible results. Does not guarantee absolute determinism, but ensures the model’s “random” choices are the same on each call.                                                                                                                                                                                                                                                                                                                          |
| **topK**                       | Top-K sampling — the model considers only the K most probable tokens for the next token (integer ≥0).                            | Field in `ChatParamsDto` and `ProviderCallOptions`; override only from body (no merge with YAML `defaults`). **Anthropic:** `top_k` (priority over `topP` / `temperature`). **Google:** `topK` in `buildGenerationConfig`. Requires an entry in `allowOverrides`.                                                                                                                                                                                                                                                                                                                      |
| **responseFormat** (JSON mode) | Forces the structure of the model response. `{ type: "json_object" }` + optional **`jsonSchema`**.                                                               | Body only (`params.responseFormat`); no merge with YAML `defaults`. **Anthropic** → `output_config.format.type: json_schema` (default schema `{ type: object, additionalProperties: true }` when `jsonSchema` is absent); **Google** → `response_format: application/json` + `response_schema`. Anthropic facade: `output_config` in the Messages API request — `anthropic-messages-integration.md`.                                                                                                                                                                             |
| **thinkingEnabled**            | Enables extended thinking/reasoning mode for reasoning-capable models (boolean).                                                                             | Field in `ChatParamsDto` and `ProviderCallOptions`; may come from body or YAML `defaults`. **Anthropic Claude Opus/Sonnet 4.5+** → `thinking: { type: 'enabled' \| 'adaptive', budget_tokens?, display }`. **Google Gemini 3.0+** → `thinkingConfig: { includeThoughts: true }`. **OpenAI** (`type: openai`) → Responses API (`reasoning.effort` + `reasoning.summary: auto`) in `responses.adapter.ts`; OpenAI facade maps `reasoning_effort` → `params.thinking*`. Requires `capabilities.thinking: true` and an entry in `allowOverrides`. **Cost:** 2–10× more tokens. |
| **thinkingBudget**             | Thinking budget/intensity: string (`"none"` \| `"minimal"` \| `"low"` \| `"medium"` \| `"high"` \| `"xhigh"` \| `"max"`) or integer (min 1024).         | Override only from body (no merge with YAML `defaults`). **Anthropic**: number → `thinking.budget_tokens`; string → `output_config.effort`. **Google Gemini 3.0+**: number → `thinkingConfig.thinkingBudget`; string → `thinkingConfig.thinkingLevel`. **OpenAI**: string effort → `reasoning.effort` (Responses API). **Cross-validation:** when number, requires `maxOutputTokens >= thinkingBudget + 512`. Requires an entry in `allowOverrides`.                                                                                                                               |

## Warning codes

Warnings (field `warnings` in the response) inform the client about parameters accepted in the body but **not passed to the provider**. Warnings **do not** block the call — HTTP response 200/201.

| Code                        | Meaning                                                                                                                                                        |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PARAM_IGNORED_BY_PROVIDER` | A parameter from `params` (e.g. `frequencyPenalty`, `presencePenalty`, `seed`) is not supported by the selected provider (`anthropic` / `google`) and was ignored. |

**Note:** OpenAI and Anthropic Messages API facades **do not** expose the `warnings` field in the response (vendor format compatibility). Warnings are available **only** in the native gateway API (`POST /api/v1/chat` and SSE `done`).

## Error codes (stable)

Codes are part of the API contract. Clients should base logic on `code`, not on `message`.

| Code                         | Meaning                                                                                                                                                                                                                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VALIDATION_FAILED`          | Request body or parameters failed validation.                                                                                                                                                                                                                                               |
| `MODEL_ALIAS_NOT_FOUND`      | The given `modelAlias` does not exist in gateway configuration.                                                                                                                                                                                                                                          |
| `MODEL_NOT_ALLOWED`          | Model, mode (e.g. streaming), or a field in `params` (e.g. `temperature`) is not allowed by policy (`allowOverrides`).                                                                                                                                                                           |
| `PROVIDER_UNSUPPORTED`       | `providerInstance` from config is not registered at runtime (no factory for `type`, or instance failed bootstrap).                                                                                                                                                                   |
| `PROVIDER_AUTH_FAILED`       | Authentication error to the provider (e.g. bad key).                                                                                                                                                                                                                                               |
| `PROVIDER_RATE_LIMITED`      | Provider returned a limit (429) — SDK mapping in `provider-error.mapper.ts`.                                                                                                                                                                                                                        |
| `RATE_LIMITED`               | Limit imposed by the gateway: **`SmartRateLimitGuard`** (RPS/burst/streams per client key) and **cooldown** after upstream 429 (`prepareRequestForExecution` → `checkCooldown`; `ChatErrorHandlerService` → `setCooldown` after a provider error — applies to JSON chat and stream). HTTP **429**. |
| `PROVIDER_TIMEOUT`           | Exceeded `policy.timeoutMs` for a provider call attempt (`ResilientExecutor`); the in-flight request is cancelled via `AbortSignal` (best-effort on the SDK side). HTTP **504**.                                                                                                                                                                                                                                                     |
| `PROVIDER_UNAVAILABLE`       | Provider returned a 5xx error or is unavailable.                                                                                                                                                                                                                                                   |
| `STREAMING_NOT_SUPPORTED`    | Selected model/provider does not support streaming.                                                                                                                                                                                                                                                    |
| `TOOLS_NOT_SUPPORTED`        | Request contains tooling (`tooling`, `tool` in messages, `toolCalls`), and the alias lacks `capabilities.tools: true` in YAML.                                                                                                                                                                            |
| `THINKING_NOT_SUPPORTED`     | Request contains `thinkingEnabled: true` (in `params` or defaults), and the alias lacks `capabilities.thinking: true` in YAML. HTTP **400**.                                                                                                                                                             |
| `GATEWAY_KEY_NOT_CONFIGURED` | No key allowlist at runtime (e.g. `gatewayKey` not registered in configuration) — **500**, guard returns this code (`GatewayKeyGuard`). With a correct start from `gateway.config.yaml` and env this scenario does not occur.                                                                         |
| `GATEWAY_KEY_MISSING`        | Missing `X-Gateway-Key` header for a protected endpoint — **401** (`GatewayKeyGuard`).                                                                                                                                                                                                            |
| `GATEWAY_KEY_INVALID`        | `X-Gateway-Key` value outside the allowlist — **403** (`GatewayKeyGuard`).                                                                                                                                                                                                                           |
| `INTERNAL_SERVER_ERROR`      | Unhandled server exception; default fallback in `GlobalExceptionFilter` when no explicit `code`.                                                                                                                                                                                                |

## HTTP codes (mapping)

| HTTP | Typical `code` (explicit in exception payload)                        | Fallback `DEFAULT_HTTP_STATUS_TO_CODE` |
| ---- | ----------------------------------------------------------------- | -------------------------------------- |
| 400  | `VALIDATION_FAILED`, `MODEL_ALIAS_NOT_FOUND`, `MODEL_NOT_ALLOWED` | `VALIDATION_FAILED`                    |
| 401  | `GATEWAY_KEY_MISSING` (`GatewayKeyGuard`)                         | `PROVIDER_AUTH_FAILED`                 |
| 403  | `GATEWAY_KEY_INVALID` (`GatewayKeyGuard`)                         | `GATEWAY_KEY_INVALID`                  |
| 429  | `RATE_LIMITED` (gateway), `PROVIDER_RATE_LIMITED` (upstream)      | `RATE_LIMITED`                         |
| 500  | `GATEWAY_KEY_NOT_CONFIGURED`, `INTERNAL_SERVER_ERROR`             | `INTERNAL_SERVER_ERROR`                |
| 502  | `PROVIDER_UNSUPPORTED`, `PROVIDER_UNAVAILABLE`                    | `PROVIDER_UNAVAILABLE`                 |
| 504  | `PROVIDER_TIMEOUT`                                                | `PROVIDER_TIMEOUT`                     |

**Rule:** domain paths (guards, `ChatService`, `provider-error.mapper.ts`) **always** set an explicit `code`. Fallback applies to exceptions without a `code` field (e.g. some Nest validation errors).

**Error envelope:** **`ErrorEnvelope`** ([`openapi.json`](../openapi.json)); `GlobalExceptionFilter` preserves `code` from the payload. Enum: `src/common/errors/api-error.code.ts` (including **`RATE_LIMITED`** and **`PROVIDER_RATE_LIMITED`**). **`requestId`**: `RequestIdMiddleware` + possible override from the exception payload in the filter; response header **`x-request-id`** set in middleware together with `req.requestId`.

Related: `openapi.json`, `api-architecture.md`, `api-documentation.md`, `anti-patterns.md`.

## Brand types (TypeScript)

The project uses **nominal types** (`Brand<K, T>`) in the runtime layer to prevent mixing semantically different values of the same primitive type. Implementation details and conventions: **`brand-types.md`**.

| Element                                       | Location                          |
| --------------------------------------------- | ------------------------------------ |
| Base type `Brand<K, T>`, `brand` / `unbrand` | `src/common/types/branded.types.ts`  |
| Validated guards (`create*`, `is*`)          | `src/common/types/branded.guards.ts` |
| Barrel export (selected types and helpers)        | `src/common/types/index.ts`          |
| Utility tests (target: 100% coverage)     | `src/common/types/branded.spec.ts`   |
| Guide                                    | **`brand-types.md`**                 |

**Brand types scope (runtime `src/`, excluding CLI):** security types (`GatewayKey`, `ProviderApiKey`, `EnvRef`), identifiers (`RequestId`, `ConversationId`, `ModelAlias`, `ModelId`, `ToolCallId`, …), metrics (`InputTokens`, `OutputTokens`, `CostUsd`, …), policy (`TimeoutMs`, `MaxAttempts`, `CacheKey`, …), `WarningCode` in `generation-warnings.ts`. Full table: `brand-types.md`.

**API boundary rule:** JSON fields in DTOs (`ChatRequestDto`, `ChatResponseDto`, `ChatWarningDto`, etc.) remain `string` / `number`; conversion to brand type happens in services / mappers after validation. OpenAPI and JSON do not see brands — this is a TypeScript-only contract.

**Warning code examples** (`WarningCode`, HTTP field `warnings[].code` as string): `PARAM_IGNORED_BY_PROVIDER` — body parameter unsupported by the provider; generated in `src/chat/helpers/generation-warnings.ts`.
